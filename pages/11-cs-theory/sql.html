SQL: DDL & DML

SQL (Structured Query Language) is used to define relational database structures and work with the records stored inside them. In this lesson, the core distinction is simple: DDL changes structure; DML works with data.

Learning Objectives

  • 11.4.2.2 Create a database structure using DDL commands: CREATE, ALTER and DROP

Conceptual Anchor

Build the Warehouse, Then Work Inside It

DDL is like constructing the warehouse: create shelves, change the layout, remove a section. DML is the work done inside it: add stock, find stock, change stock and remove stock.

DDL CREATE · ALTER · DROP
Database structure tables · columns · data types · constraints
then
DML INSERT · SELECT · UPDATE · DELETE

DDL vs DML

Feature DDL DML
Full name Data Definition Language Data Manipulation Language
Main purpose Define or modify database structure Add, retrieve, change or remove records
Main commands CREATE, ALTER, DROP INSERT, SELECT, UPDATE, DELETE
Affects Schema / structure Data / records
Decide whether the command changes structure or data.

From Data Dictionary to SQL

The data dictionary describes the intended structure. A CREATE TABLE statement implements that design.

DBMS differences

Exact data types and some ALTER TABLE syntax can differ between MySQL, PostgreSQL, SQL Server, Oracle and MS Access. In this lesson, focus on the common SQL ideas and the syntax used in the examples.

ALTER TABLE

ALTER TABLE Student ADD Phone VARCHAR(15); ALTER TABLE Student DROP COLUMN Phone;

DROP TABLE

DROP TABLE Student;

DROP removes the table

DROP TABLE Student; removes the table structure and its data. It is not the same as deleting selected records.

SELECT — Retrieve Data

2 SELECT as a query builder

SELECT Which columns?
FROM Which table?
WHERE Which rows?
ORDER BY In what order?
SELECT Name, Age FROM Student WHERE Class = '11A' ORDER BY Name ASC;
Part Question answered
SELECT Name, Age Which columns should be returned?
FROM Student Which table contains the data?
WHERE Class = '11A' Which records should be included?
ORDER BY Name ASC How should the result be sorted?

Core SELECT Patterns

-- All columns, all rows SELECT * FROM Student; -- Specific columns SELECT Name, Class FROM Student; -- Filter rows SELECT * FROM Student WHERE Age >= 16; -- Combine conditions SELECT Name FROM Student WHERE Age >= 16 AND Class = '11A'; -- Pattern matching SELECT Name FROM Student WHERE Name LIKE 'A%'; -- Sort SELECT Name, Age FROM Student ORDER BY Age DESC;

Comparison & Logical Operators

Operator Meaning Example
= equal to Class = '11A'
<> not equal to Class <> '11A'

Translate the Requirement into SQL

Requirement SQL
Show names of students in class 11A SELECT Name FROM Student WHERE Class = '11A';
Show students older than 16, oldest first SELECT * FROM Student WHERE Age > 16 ORDER BY Age DESC;
Show names beginning with A SELECT Name FROM Student WHERE Name LIKE 'A%';

INSERT, UPDATE & DELETE

INSERT — Add a Record

INSERT INTO Student (StudentID, Name, Age, Email, Class) VALUES ('S001', 'Ali', 16, 'ali@nis.edu.kz', '11A');

UPDATE — Change Existing Data

UPDATE Student SET Class = '11B' WHERE StudentID = 'S001';

DELETE — Remove Records

DELETE FROM Student WHERE StudentID = 'S003';

UPDATE or DELETE without WHERE

UPDATE Student SET Class = '11B'; changes every row. DELETE FROM Student; removes every row. Use WHERE when the task targets specific records.

DELETE ≠ DROP

DELETE removes records but keeps the table. DROP TABLE removes the table itself.

11.4.2.4 — SELECT from multiple tables (JOIN)

This is the next syllabus step rather than the core LO of this page. JOIN combines related records using matching key values.

SELECT s.Name, e.Grade FROM Student s INNER JOIN Enrolment e ON s.StudentID = e.StudentID;
SELECT s.Name, c.CourseName, e.Grade FROM Student s INNER JOIN Enrolment e ON s.StudentID = e.StudentID INNER JOIN Course c ON e.CourseID = c.CourseID;

The JOIN works because the normalized tables are connected by primary-key / foreign-key relationships.

Common Pitfalls

Text values without quotes

Write WHERE Class = '11A', not WHERE Class = 11A.

Missing WHERE in UPDATE / DELETE

Without a condition, the command can affect every record.

Mixing column and value counts

The number and order of values should match the listed columns in an INSERT INTO ... VALUES ... statement.

DELETE vs DROP

DELETE removes records. DROP TABLE removes the table structure itself.

WHERE before FROM

Basic query order is SELECT ... FROM ... WHERE ... ORDER BY ....
