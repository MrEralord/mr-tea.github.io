Software Development Life Cycle (SDLC)

The Software Development Life Cycle (SDLC) is a structure that determines the sequence of execution and interrelationships of processes, actions, and tasks throughout the creation of software[cite: 3]. Different models (like Waterfall, Spiral, or Agile) organise these stages depending on the specific conditions, scale, and complexity of the project[cite: 3].

Conceptual Anchor

The House-Building Analogy

Building software is like building a house. You need to: define the problem (Definition), understand what the client wants (Analysis), draw blueprints (Design), build it (Implementation), check for faults (Testing), move the client in (Installation), and fix problems over time (Maintenance)[cite: 2]. The SDLC is the overarching blueprint for this entire process.

The Core Stages of SDLC

[ВСТАВИТЬ КАРТИНКУ: Круговая диаграмма SDLC (Requirement Analysis, Design, Implementation, Testing, Evolution). Взять со 2 слайда презентации "System lifecycle stages.pptx"]

While different models arrange the flow differently, almost all software development goes through these fundamental stages[cite: 2]:

Stage Key Activities[cite: 2]
1. Definition Interviews with management and staff to define the core problem and understand limitations of the current system.
2. Investigation & Analysis Detailed studies and questionnaires to fully understand requirements and create a Requirements Specification.
3. Design Planning how the project will be carried out and defining system architecture based on agreed requirements.
4. Implementation Software developers begin writing the code and physically developing the new system.
5. Testing Ensuring the system works as expected using methodologies like Black Box, White Box, and Dry Run Testing.
6. Evaluation Reviewing the overall project to check if the finished solution meets requirements and actually solves the problem.
7. Maintenance Updating the system, fixing late bugs, and ensuring long-term operation.

Comparison of SDLC Models

1. Waterfall Model

One of the oldest models involving the sequential passage of stages. Each stage must be completed completely before the beginning of the next[cite: 3].

[ВСТАВИТЬ КАРТИНКУ: Схема Waterfall Model со ступеньками (Requirements -> Design -> Implementation -> Verification -> Maintenance). Взять со слайда 7 "Life cycle models.pptx"]
Advantages[cite: 3] Disadvantages[cite: 3]
Stages and activities are well defined; structured approach. Assumes requirements can be frozen early on.
Easy to manage, plan, and schedule because each phase has specific deliverables. Very difficult to go back to any stage after it has finished.
Excellent for projects with clearly defined requirements[cite: 3]. Adjusting scope is difficult and expensive.

2. V-Shaped Model

An improved version of the waterfall model focused heavily on quality. For each development stage, it provides its own corresponding testing stage[cite: 3]. Applicable to systems crucial for smooth operation[cite: 3].

[ВСТАВИТЬ КАРТИНКУ: Схема V-Model (Planning -> Requirements... -> Unit Testing -> Implementation). Взять со слайда 19 "Life cycle models.pptx"]
Advantages[cite: 3] Disadvantages[cite: 3]
Higher chance of success over waterfall due to early test plan development. Very inflexible; does not provide a clear path for problems found during testing.
Verification and validation happen in early stages. No early prototypes of the software are produced.

3. Spiral Model

Combines waterfall and incremental approaches with a major emphasis on risk analysis[cite: 3]. It works well for mission-critical business tasks where failure is incompatible with company activities[cite: 3].

[ВСТАВИТЬ КАРТИНКУ: Спиральная диаграмма (Determine Objectives, Risk Analysis, Development, Review). Взять со слайда 12 "Life cycle models.pptx"]
Advantages[cite: 3] Disadvantages[cite: 3]
Estimates (budget, schedule) become more realistic as work progresses. High cost and time to reach the final product.
Manages risks effectively by developing the system in phases. Needs special skills to evaluate risks and assumptions.

4. Incremental & Iterative (Agile/Scrum)

In the incremental model, total requirements are divided into modules, forming a "multi-waterfall" lifecycle[cite: 3]. Agile is a flexible development methodology where the customer observes the result after each iteration (sprint)[cite: 3].

[ВСТАВИТЬ КАРТИНКУ: Scrum Process (Product Backlog -> Sprint -> Finished Work). Взять со слайда 9 "Life cycle models.pptx"]
Advantages[cite: 3] Disadvantages[cite: 3]
Produces business value early; project issues are detected earlier. Lack of specific wording of results makes it difficult to estimate final cost and effort.
Face-to-face communication and continuous customer input leaves no space for guesswork. Requires heavy documentation and more customer involvement.

Pitfalls & Common Errors

Misunderstanding the Iterative Process

It is a common mistake to think the final product is delivered at the end of an iterative cycle. In reality, each iteration produces a working, albeit incomplete, version of the software that is reviewed and expanded upon in the next cycle[cite: 3].

Assuming Waterfall is "Bad"

While Agile is popular, Waterfall is not inherently bad. It remains highly effective for projects where the requirements are easily understood, strictly defined, and will not change (e.g., medical devices, construction software)[cite: 3].

Independent Study Tasks

Apply

Case Study: School Guest Registration
The school has a problem with the registration of guests. Currently, security writes guest data manually in a notebook, which takes a lot of time and lacks control (e.g., they cannot verify names properly). The client wants to change this manual system to an electronic one. When a guest arrives, security should take a picture and record their Name, IIN, and time of arrival/departure into a database[cite: 1].

Task: Analyze how the development of this system would differ if you used the Waterfall model versus the Iteration model. Which model would you recommend to the school administration and why?

Analyze

Dave is a senior manager with Facebook. He has an idea for a new product but is currently unsure of how the application will look. The budget for this project is endless[cite: 3].
Task: Why are the Waterfall and V-Models completely unsuitable for Dave's project? Which model (Prototyping, Spiral, or Agile) would you select to handle the high risk and changing requirements[cite: 3]?

Self-Check Quiz

1. In which SDLC stage do developers begin to actually write the code?
Click to reveal: The Implementation stage[cite: 2].
2. Which methodology is described as a cascading format where one stage must completely finish before the next begins?
Click to reveal: The Waterfall Model[cite: 3].
3. What is the main difference between the Spiral and Incremental models?
Click to reveal: Incremental is broken into separate functional units completed individually. The Spiral model works in cycles with heavy emphasis on evaluating and resolving risks before generating new requirements[cite: 3].
4. Why might the feedback stage lead to a new cycle in iterative development?
Click to reveal: If feedback contains negative comments or new requirements, it drives a new development and testing phase to improve the prototype[cite: 3].
