Software Development Life Cycle

The Software Development Life Cycle (SDLC) is the sequence of stages used to analyse, design, create, test, introduce and improve an information system. A life cycle model determines how these stages are organised and repeated during development.

Learning Objectives

  • 11.2.1.1 Describe the stages of the Software Development Life Cycle.
  • 11.2.1.2 Analyse the advantages and disadvantages of cyclical, waterfall and spiral models.

Success Criteria

By the end of the lesson, I can:

  • name and explain the main stages of the SDLC;
  • distinguish between Waterfall, Cyclical and Spiral models;
  • identify advantages and disadvantages of each model;
  • select a suitable model for a given scenario;
  • justify my choice using details from the scenario.

What is the SDLC?

Think about building a house

Before building starts, the problem and requirements must be understood. Then plans are produced, construction begins, the result is checked, the owner starts using it, and problems are corrected later. Software development follows the same basic idea.

The SDLC stages describe the work that must be carried out. The SDLC model describes the order in which that work happens and whether stages are repeated.

System Life Cycle Stages

The lesson materials use the following nine-stage system life cycle.

1. Definition
Define the problem and identify why a new or improved system is needed. Interviews with management and staff may be used to understand the current problem.
2. Investigation & Analysis
Study the existing system and collect detailed information about user requirements. Interviews, questionnaires and observations can be used.
3. Design
Plan how the proposed solution will work. This may include user interfaces, data structures, inputs, outputs and processing.
4. Implementation
Developers create the solution and write the program code based on the approved design.
5. Testing
Check that the completed system works correctly and produces the expected results. Testing may include black-box, white-box and dry-run testing.
6. Installation
Introduce the new system into the organisation so users can begin working with it.
7. Documentation
Produce user and technical documentation explaining how to use, maintain and support the system.
8. Evaluation
Review the finished solution and determine whether it meets the original requirements and solves the original problem.
9. Maintenance
Correct faults, adapt the system to new requirements and keep it working after implementation.

Exam tip

Do not confuse stages with models. Definition, analysis, design and testing are stages. Waterfall, Spiral and Cyclical are models that organise those stages.

1. Waterfall Model

Waterfall is a sequential model. Each stage is completed before development moves to the next stage. Returning to an earlier completed stage is difficult.

1 Basic flow

Requirements → Design → Implementation → Testing → Installation → Maintenance

Advantages Disadvantages
Stages and deliverables are clearly defined. Changing requirements after development has started is difficult.
Easy to plan, manage and schedule. Going back to a previous stage can be expensive.
Suitable when requirements are clear and stable. Users may wait a long time before seeing the completed system.

Suitable scenario

Waterfall can work well when the customer already knows exactly what is required and major changes are unlikely.

2. Cyclical / Iterative Model

In a cyclical model, development happens in repeated cycles. A working version is produced, reviewed and improved during the next cycle.

2 Basic flow

Plan → Design → Develop → Test → Feedback → Improve → Repeat

Advantages Disadvantages
Users can see versions of the product during development. Final cost and development time can be harder to predict.
Feedback can be used to improve the next version. Repeated changes can extend the project.
Problems can be identified earlier. Regular customer involvement may be required.

Why is feedback important?

If feedback is positive, the team knows the current solution is meeting user needs. If feedback identifies problems or new requirements, another development and testing cycle can begin.

3. Spiral Model

The Spiral model combines repeated development cycles with strong emphasis on risk analysis. Each loop of the spiral develops the solution further.

3 One spiral cycle

Determine objectives → Identify and resolve risks → Develop and test → Review and plan the next iteration

Advantages Disadvantages
Risks are identified and considered throughout development. The process can be expensive and time-consuming.
Changes can be introduced between cycles. Risk analysis requires specialist knowledge.
Useful for large, complex or high-risk projects. Can be unnecessarily complex for a small simple project.

Other Models You Should Recognise

V-Model
A development model related to Waterfall in which development stages are paired with corresponding verification and validation activities.
Incremental Model
The complete system is divided into smaller functional parts. Individual increments are developed and later combined into the full system.
Agile / Scrum
A flexible iterative approach where development is organised into short cycles or sprints and customers can review progress regularly.
Prototyping
An early model of the proposed system is created so users can review the interface and requirements before the final product is developed.

Waterfall vs Cyclical vs Spiral

Feature Waterfall Cyclical Spiral
Structure Sequential Repeated cycles Repeated risk-focused cycles
Changing requirements Difficult Easier Easier between cycles
User feedback More limited during development Regular Used during review and planning
Risk analysis Not the main feature Problems identified through cycles Central feature
Suitable for Clear and stable requirements Changing requirements and regular feedback Large, complex and higher-risk projects

How to justify your answer

Do not write only: "I would choose Spiral because it is better." Link your answer to the scenario: "The project contains significant uncertainty and risk, so Spiral is appropriate because risk is analysed during every development cycle."

Case Study: School Guest Registration

1 Current problem

When a guest comes to school, security writes the visitor's data manually in a notebook. This takes time and makes it difficult to control and verify visitor information.

2 Client requirements

The school wants an electronic guest registration system. Security should be able to:

  • take a photograph of the guest;
  • enter the guest's full name;
  • enter the guest's IIN;
  • record arrival time;
  • record departure time;
  • save the information in a database.

3 Possible main form

Guest photograph Camera preview / Capture Photo button
Full Name Text input
IIN 12-digit text / number input with validation
Arrival Time Automatically generated time or time input
Departure Time Updated when the guest leaves
Save Store the record in the database

Common Mistakes

“Waterfall is always bad”

Waterfall can be suitable when requirements are already clear, stable and unlikely to change.

“Iterative means the final system is produced only at the end”

Iterative development produces versions of the system during development. Each version can be reviewed and improved.

“Spiral is just another name for Iterative”

Both use cycles, but the Spiral model gives special importance to identifying and resolving risks during each cycle.

Self-Check Quiz

1. Which SDLC stage is used to define the original problem?
Definition.
2. At which stage do developers write the program code?
Implementation.
3. Which model completes one stage before starting the next?
Waterfall.
4. Why may feedback start another development cycle?
Feedback may identify errors, weaknesses or new requirements, so another cycle of development and testing is needed.
5. What is the key feature of the Spiral model?
Risk analysis is performed as part of each development cycle.
6. What two questions are important during Evaluation?
Does the completed solution meet the requirements? Does it solve the original problem?
