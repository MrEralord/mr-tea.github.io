Prototyping & Interface Design

During the design phase of the System Development Life Cycle (SDLC), developers construct prototypes — interactive models or mockups of the proposed system. Prototyping allows end-users and developers to test interface layouts, refine input/output forms, and validate functional requirements long before writing database or backend code.

Conceptual Anchor

The Architectural Clay Model

Before constructing a \$50-million skyscraper, architects build a 3D clay or digital cardboard model. Clients inspect the shape, walk through the simulated rooms, and request modifications to the layout. Changing clay takes minutes; modifying concrete pillars once poured costs millions. A software prototype serves the identical purpose for user interfaces and workflow navigation.

Rules & Theory

1. Prototype Fidelity: Low-Fidelity vs High-Fidelity

Dimension Low-Fidelity (Low-Fi) High-Fidelity (High-Fi)
Format Paper sketches, whiteboard mockups, rough wireframes Clickable digital mockups (Figma, Adobe XD) or basic HTML/CSS forms
Speed & Cost Extremely fast, cheap, disposable More time-consuming, requires specialized UI tools
Primary Focus Content organization, layout hierarchy, information flow Visual look-and-feel, exact fonts, color palette, interactive responsiveness
Type of Prototype Throwaway Prototyping: Created to confirm requirements and then discarded Evolutionary Prototyping: Incrementally refined until it becomes the final production system

2. Advantages & Disadvantages of Prototyping (11.2.2.4)

Advantages Disadvantages
Active User Involvement: End users interact directly with tangible screens, discovering missing needs early. False Sense of Completion: Non-technical clients think the system is 90% done because the screens look real, ignoring backend complexity.
Clarifies Ambiguous Requirements: Resolves vague business rules before costly database architecture is built. Scope Creep: Constant feedback loops can lead clients to request endless new features without formal change requests.
Early Usability Validation: Confirms navigation flow, button ergonomics, and accessibility early. Time & Resource Overhead: Building multiple prototype revisions can delay initial delivery if not strictly time-boxed.

Pitfalls & Common Errors

Confusing Wireframes with Graphic Design

In low-fidelity prototyping, do not waste hours picking color gradients and realistic stock photos. Focus on layout, functional flow, data entry fields, and user feedback.

Misusing Selection Controls

Using checkboxes when only one choice is permitted (e.g. Payment Method: Credit Card vs Cash) invites conflicting data. Always use radio buttons or a dropdown for mutually exclusive options.

Pro-Tips for Exams

Exam Checklist

  • Throwaway vs Evolutionary: In throwaway prototyping, the code/sketches are discarded once requirements are locked. In evolutionary prototyping, the prototype evolves into the final delivered software.
  • Two key advantages for exam questions: 1) Early identification of user errors/misunderstandings, 2) Increased client satisfaction through direct participation.
  • Two key disadvantages: 1) Client may demand rapid delivery believing software is already complete, 2) Scope creep and cost overruns.
