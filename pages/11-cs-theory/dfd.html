Data Flow Diagrams (DFD)

A Data Flow Diagram shows how data enters a system, how processes transform it, where it is stored and what data leaves the system. This lesson uses the same notation and rules as the classroom materials: Context Diagram / Level 0 → Level 1 DFD.

Learning Objective

  • 11.2.2.1 Create a first-level data flow diagram (DFD) to represent input, processing, storage, and output in computing systems
Purpose Symbols Level 0 Level 1 Rules Errors Labs Practice

What a DFD Shows

Follow the Data

A DFD focuses on the flow of data through a system. It identifies the sources and destinations of data, the processes that transform the data, and the stores where data is held.

Input Data enters from an external entity
Processing A process transforms the data
Storage Data may be read from or written to a store
Output Data leaves for an external entity

DFD vs Flowchart

DFD Flowchart
Shows flow of data Shows flow of control / sequence
Uses entities, processes, data stores and data flows Uses process, decision, input/output and control-flow symbols
Does not model if/else branches or loops as control elements Can show decisions, branches and loops
Logical DFD vs Physical DFD

Logical DFD: focuses on what happens to the data and how information moves through the business/system processes.

Physical DFD: is closer to implementation and shows how the data flow is actually carried out.

The Four DFD Symbols

Element Represents Naming rule Good example
External Entity Source or destination outside the system Noun Customer, Bank
Process Activity that transforms/manipulates data Verb phrase Calculate Pay
Data Store Repository of stored data Noun D1 Employee File
Data Flow Movement of data between elements Name of the data Hours Worked

Name the data, not the action

Process: Process Payment ✓. Data flow: Payment Details ✓. A data-flow label such as “Send Payment” describes an action rather than the data itself.

Context Diagram / Level 0

The Context Diagram is the simplest DFD. It shows the whole system as one process, the external entities that interact with it, and the major data flows entering and leaving it. Data stores are not shown at this level.

1 How to draw Level 0 from a scenario

  • Identify the main system — this becomes the single process.
  • Identify the external entities that interact with it.
  • Identify the input data supplied by each entity.
  • Identify the output data returned to each entity.
  • Label every data flow clearly.

Classroom convention

In these lesson materials, Context Diagram and Level 0 refer to the same high-level diagram.

Level 1 DFD

A Level 1 DFD decomposes the single Level 0 process into the system's major processes. It can also introduce the data stores used by those processes.

2 Level 0 → Level 1

Start with the Context Diagram. Break the one system process into smaller processes, identify the required data stores, keep the external entities, and ensure that the major data flows crossing the system boundary are still represented.

Check Level 0 Level 1
Number of system processes One Several major processes
External entities Shown Shown
Major boundary data flows Shown Still represented
Data stores Not shown May be introduced

Level 1 Rules

Rule Meaning
Entity → Entity Not directly. Data must pass through a process.
Entity ↔ Data Store Not directly. A process must read/write the data.
Data Store → Data Store Not directly. A process must move/transform the data.
Process input/output Each process should have meaningful input and output flows.
Labels Entities, processes, stores and flows should all be labelled.
Layout Avoid crossing data-flow lines where possible; keep the diagram readable.

Exam drawing tip

Put major processes near the centre. Keep external entities and data stores toward the edges. Clear spacing makes direction and labels much easier to mark.

Black Hole, Miracle & Gray Hole

Error Pattern Why it is wrong
Black Hole Input(s), but no output Data enters the process but nothing meaningful leaves it.
Miracle Output(s), but no input The process produces data from nowhere.
Gray Hole Input exists, but is insufficient for the output The stated input cannot logically produce the stated output.

Common Pitfalls

Drawing a flowchart instead of a DFD

Do not add decision diamonds, loops or control-flow arrows to a DFD.

Using actions as data-flow labels

Use Order Details, not “Send Order”. Use a verb phrase for the process instead.

Putting data stores in the Context Diagram

In the classroom convention, Level 0 shows one process, external entities and major flows only.

Losing an external flow during decomposition

If Level 0 shows an external entity/data flow, Level 1 should still represent that system-boundary interaction.

Direct Entity ↔ Store connection

An external entity cannot read from or write directly to a data store; use a process.

Exam Practice

Q1: State two features of a Context Diagram / Level 0 DFD. [2]

Reveal marking points
One process represents the whole system [1]. Shows external entities and major data flows to/from the system [1]. Accept: does not contain data stores.

Q2: Explain why an external entity must not be connected directly to a data store in a DFD. [2]

Reveal marking points
A process must handle/transform/control the data movement [1]. The entity should exchange data with a process, which then reads/writes the store [1].

Q3: A process has two input flows but no output flow. Name the DFD error and explain it. [2]

Reveal marking points
Black Hole [1]. Data enters the process but no data leaves / no output is produced [1].

Q4: A Level 0 diagram shows Customer → Order System: Order, and Order System → Customer: Invoice. State what must happen to these boundary flows when the system is decomposed to Level 1. [2]

Reveal marking points
The Customer must still be represented as an external entity [1]. The Order input and Invoice output must still be represented through one or more Level 1 processes [1].
