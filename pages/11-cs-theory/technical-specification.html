Technical Specification & System Requirements

Before procuring equipment or deploying software, systems analysts must create a Technical Specification. This formal document quantifies the minimum hardware requirements (CPU, RAM, storage, network) and provides a rigorous justification for software selections (OS, DBMS, security tools) to guarantee performance, reliability, and cost-effectiveness.

Learning Objectives

Conceptual Anchor

The Commercial Aircraft Engine Specification

When an airline orders a cargo plane, they don't just ask for "a big engine". They specify the minimum thrust in kilonewtons, fuel burn rate per hour, wingspan tolerance, and certified navigation avionics. If you undersize the engine, the plane won't take off; if you oversize it, fuel costs bankrupt the airline. System sizing balances workload requirements with fiscal reality.

Rules & Theory

1. Sizing Hardware Components (11.3.2.1)

Hardware Component Key Measurable Metrics Design Considerations
Processor (CPU) Cores, Threads, Clock Speed (GHz), Architecture (x86-64 / ARM) Single-threaded throughput vs multi-threaded concurrent user load. Database and web servers require high core counts.
Primary Memory (RAM) Capacity (GB), Technology (DDR4 / DDR5), ECC (Error-Correcting Code) Must accommodate OS overhead, DBMS buffer cache, active web worker threads, and peak concurrent user sessions in memory.
Secondary Storage Capacity (GB / TB), Medium (NVMe SSD vs HDD), IOPS, Redundancy SSD for active database transactions; high-capacity HDDs in RAID arrays (RAID 1 / RAID 5) for cold storage and automated daily backups.
Network Interface (NIC) Bandwidth (1 Gbps / 10 Gbps), Full Duplex, Latency Calculated via formula: $\text{Bandwidth} \ge \text{Concurrent Users} \times \text{Average Payload Size} \times \text{Safety Factor}$.
Peripherals Barcode scanners, thermal receipt printers, UPS (Uninterruptible Power Supply) Ensures business continuity during power outages and specialized physical data capture.

2. Justifying Software Choices (11.3.1.4)

Software Layer Candidate Options Typical Justification Criteria
Operating System (OS) Linux (Ubuntu Server) vs Windows Server Linux: Zero licensing fees, lower resource footprint, high stability, standard package management.
Windows: Native Active Directory support, familiar GUI for non-CLI sysadmins.
Database Engine (DBMS) PostgreSQL / MySQL vs MongoDB Relational (PostgreSQL): Strong ACID compliance, foreign key relational integrity, SQL standardization for structured financial and student records.
Web Server Nginx vs Apache Nginx: Event-driven asynchronous architecture handles tens of thousands of concurrent connections with low memory usage.
Security & Backup OpenSSL, UFW Firewall, Borg Backup / Restic End-to-end TLS encryption in transit, automated encrypted off-site snapshots for disaster recovery.

Worked Examples

1 Case Study: School Information System (SIS) Technical Specification

Technical requirements for a school serving 1,200 students and 150 staff members:

Category Minimum Specification Engineering Justification
Server CPU 8-Core, 16-Thread (AMD EPYC or Intel Xeon @ 3.0 GHz) Handles concurrent exam submissions and report card generation during end-of-term peaks without CPU bottlenecks.
Server RAM 32 GB DDR4 ECC RAM Allows caching the entire relational database index pool in memory for sub-millisecond query responses.
Server Storage 2 × 1 TB NVMe SSD in RAID 1 (Mirroring) Provides high write speeds for logging and protects against immediate data loss if one physical drive fails.
Server OS Ubuntu Server 24.04 LTS (64-bit) 5-year guaranteed security support, zero license cost, robust security updates.
Database PostgreSQL 16 Guarantees relational integrity, supports complex analytical queries, and prevents race conditions in grade recording.

Pitfalls & Common Errors

Vague Hardware Descriptions

Writing "a fast computer" or "plenty of hard drive space" in an exam or specification earns zero marks. Specifications must contain concrete numerical values and units (e.g., "Quad-Core 2.5 GHz CPU, 16 GB DDR4 RAM, 512 GB SSD").

Sizing for Average Load Instead of Peak Load

Systems fail on the first day of school or during Black Friday because hardware was dimensioned for average monthly traffic instead of peak concurrent user spikes.

Pro-Tips for Exams

Exam Checklist

  • Always link requirement to purpose: Don't just say "Needs an SSD"; say "Needs an SSD to provide high IOPS and fast retrieval times when searching the customer database."
  • Software justification keywords: Mention licensing costs (TCO), security, cross-platform compatibility, stability, and available technical support.
  • Hardware vs Software: Make sure you never list an Operating System or Anti-Virus under hardware!
