Game Loop

The game loop is the heartbeat of a real-time game. While the application is running, it repeatedly handles events, updates game state, renders the next frame, and controls the speed of the cycle.

Conceptual Anchor

The Film Projector Analogy

A film creates the illusion of motion by showing many still frames in rapid succession. A game does the same thing, except each frame is produced by code: read input → update state → draw the current state → show the frame → repeat.

Anatomy of the Game Loop

running = True while running: for event in pygame.event.get(): if event.type == pygame.QUIT: running = False # update game state screen.fill(BLACK) # draw current game state pygame.display.flip() clock.tick(FPS) pygame.quit()
while running: Repeat frames

The program keeps producing frames while the control variable remains True.

pygame.event.get() Handle events

Retrieve queued PyGame events so the application can react.

screen.fill(...) pygame.display.flip() Render

Prepare the current frame and then make the complete display Surface visible.

clock.tick(FPS) Control speed

Limit the loop so it does not run unrestricted as fast as the CPU allows.

How the loop ends

When a pygame.QUIT event is found, the program sets running = False. The current iteration finishes, the while condition fails on the next check, and execution continues after the loop to pygame.quit().

Event Queue

Operating system / devices

Mouse movement, keyboard actions and window controls generate events.

PyGame event queue

Events wait in a queue until your program retrieves and handles them.

pygame.event.get()

Gets the queued events so a for event in ... loop can process them.

Event queue
Events returned for processing
Add some events, then call pygame.event.get().

Why process events regularly?

The event queue has a limit and should be serviced every frame. If your application stops processing events for too long, the operating system may consider the program unresponsive.

                             Pitfalls & Common Errors
                        


                        

                            
 Not processing events

                            

                                A game window must keep servicing its event queue. Otherwise it can
                                become unresponsive and the operating system may report it as frozen.
                            

                        


                        

                            
 No clock.tick() = unrestricted loop speed

                            

                                Without an FPS limit, the loop can run as quickly as the machine allows,
                                wasting resources and making frame-dependent behaviour inconsistent.
                            

                        


                        

                            
 Drawing before clearing

                            

                                If you draw an object and then call screen.fill(),
                                the background covers that object before the frame is shown.
                            

                        


                        

                            
 Missing display.flip()

                            

                                You can prepare a new frame on the Surface but still fail to show it.
                                The display update belongs after drawing the current frame.
                            

                        


                        

                            
 Creating Clock() inside every frame

                            

                                Create the Clock once before the loop, then call
                                clock.tick() each iteration.
                            

                        


                        

                            
 pygame.quit() inside the loop

                            

                                Normally pygame.quit() belongs after the loop finishes.
                                Calling it every frame uninitialises modules while the program is still running.

                                Q2: Explain why pygame.event.get() must be called regularly. [2]
                            


                            

                                Reveal marking points
                                
It retrieves/processes queued application events.
                                    If the queue is not serviced, the application may become unresponsive and events can
                                    be lost when the queue fills.

                            

                        


                        

                            

                                Q3: State the correct rendering order. [3]
                            


                            

                                Reveal marking points

                                    2. Draw the current game state
                                    3. Update/show the display with flip() or an appropriate display update

                            

                        


                        

                            

                                Q4: A game uses clock.tick(50). Calculate the ideal
                                time available per frame in milliseconds. [2]
                            


                            

                                Reveal marking points
                                
1000 ÷ 50 = 20 ms per frame.
