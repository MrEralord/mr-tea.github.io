Tracing & Debugging

Tracing means stepping through program code and recording how variables and output change. Debugging means locating, understanding and fixing errors. These are general techniques you can apply to any program.

Conceptual Anchor

The Detective Analogy

Tracing code is like being a detective examining evidence step by step. A trace table is your evidence notebook: you record variable values and output as execution progresses. Debugging is the investigation that finds the line or state that caused the problem.

Trace Table Method

1Create columns

Use one column for each changing variable and an Output column when needed.

2Follow execution

Use the real control flow. Selection may skip lines; loops may repeat them.

3Record changes

Write values exactly as Python calculates them.

4Record output

Whenever print() executes, add its result to the Output column.

How many rows?

A row may represent a statement execution, one loop iteration, or a meaningful state change depending on the question. The important rule is consistency: do not skip a value change that is needed to explain the result.

Three Types of Errors

Syntax Error

Python cannot parse the program because a language rule has been broken.

print("Hi"

Runtime Error

The program starts, but an invalid operation occurs while it is running.

10 / 0

Logic Error

The program runs, but the algorithm or formula produces the wrong result.

area = length + width

Common Python Errors

SyntaxError

Missing colon, bracket or quote. Check punctuation and syntax.

IndentationError

Invalid or inconsistent indentation.

NameError

An undefined or misspelled name is used.

TypeError

An operation receives an inappropriate type.

ValueError

Example: int("abc").

ZeroDivisionError

Division or modulo by zero.

IndexError

A sequence index is outside valid bounds.

Reading a Python Traceback

File "program.py", line 4, in <module>
answer = 10 / number

Click a traceback line.

Recommended order:
1. Read the final line.
2. Identify the error type.
3. Find the line number.
4. Inspect the source line.
5. Work backwards to find why the value became invalid.

Practical rule

Start at the bottom to identify the exception, then use the file and line information above it to locate the failing statement. In longer tracebacks, earlier lines show the chain of function calls that led there.

Pitfalls & Common Errors

Logic errors may not crash

Compare actual output with a known expected result and trace the program to find where values first diverge.

Skipping important trace steps

A trace table is evidence. Do not skip a state change needed to explain the final result.

Confusing runtime and syntax errors

A NameError occurs during execution. A syntax error prevents Python from successfully parsing the program.

Fixing without retesting

Always rerun the failing case and at least one normal case after a fix.

Pro-Tips for Exams

Trace Table Tips

  • Create columns for every changing variable required by the question.
  • Record output exactly when the print statement executes.
  • Follow the real control flow: selection may skip statements and loops may repeat them.
  • Keep types accurate — for example, / can produce a float.
  • Do not jump straight to the final answer when intermediate states are required.

Debugging Strategy

  • Read the error message and identify its type.
  • Locate the line mentioned by the traceback.
  • Trace suspicious variables or use temporary debug prints.
  • Compare actual output with an expected result you can calculate manually.
  • Retest after every fix.
