Program Compilation Stages

Compilation is the process of translating source code written in a high-level programming language into a lower-level representation that can eventually be executed by a computer. A compiler analyses the program, detects errors, creates intermediate representations, may optimise the program, and generates target code.

Learning Objectives

  • 12.5.1.3 Describe programme compilation stages: lexical analysis, syntactic analysis, semantic analysis, intermediate code generation, optimization and target code generation.
  • 12.5.1.4 Understand the role of linkers, loaders and library routines.

The Compilation Pipeline

Compilation should not be viewed as a single translation step. A modern compiler performs a sequence of specialised stages. Each stage receives an input, performs a particular job, and passes its output to the next stage.

1

Lexical Analysis

Converts characters into meaningful tokens.

Output: Token stream
2

Syntax Analysis

Checks whether tokens follow the grammar of the language.

Output: Parse Tree / AST
3

Semantic Analysis

Checks whether the program is meaningful and type-correct.

Output: Checked AST
4

Intermediate Code

Converts the program into an internal, machine-independent representation.

Output: IR
5

Optimization

Improves the code while preserving its behaviour.

Output: Optimized IR
6

Target Code

Generates instructions suitable for the target architecture.

Output: Object / Machine Code

Before We Compile — Translators Recap

Programs may be translated using different types of translator software. The three main types are compiler, interpreter and assembler.

Compiler

Translates a complete high-level program into object or target code.

Useful when: preparing the finished program for repeated execution.

Interpreter

Translates and executes program instructions during execution rather than first producing a standalone executable.

Useful when: developing, testing or debugging code.

Assembler

Translates assembly-language instructions into machine code.

Input: assembly language
Output: machine/object code

Important

Different programming languages use different execution models. For example, Java normally compiles source code into JVM bytecode, while Python implementations may compile source code into an intermediate bytecode before execution.

Conceptual Anchor

The Translation Bureau

Imagine translating a complex academic text. First, the text is separated into meaningful words and symbols — lexical analysis. Then its grammar and structure are checked — syntax analysis. Next, the translator verifies that the meaning makes sense — semantic analysis. A structured working version is produced — intermediate code. The text is then polished without changing its meaning — optimization. Finally, the result is converted into the target form required by the destination system.

One Program Through the Whole Compiler

We will use one simple statement throughout the lesson:

int result = (3 + 4) * x;

Follow the transformation

The meaning of the program does not change, but its internal representation changes at every compilation stage.

1. Lexical Analysis

Lexical analysis is the first compiler stage and is performed by a component called the lexer or scanner.

INPUT

Source code characters
→
PROCESS

Recognise lexemes and classify tokens
→
OUTPUT

Token stream

Main tasks of the lexical analyser

  • Reads the source program as a stream of characters.
  • Groups characters into meaningful units called lexemes.
  • Classifies lexemes into categories called tokens.
  • Recognises keywords, identifiers, literals, operators and punctuation.
  • Usually ignores comments and non-significant whitespace.
  • Reports lexical errors such as invalid characters or malformed literals.
  • Supplies information about identifiers to the compiler's symbol table.

Whitespace is not always meaningless

In many languages, spaces are mostly used only to separate tokens. However, some languages give whitespace syntactic meaning. Python, for example, uses indentation to represent blocks of code.

Token vs Lexeme

A lexeme is the actual sequence of characters written in the source code. A token is the category that lexeme belongs to.

while (y >= t) y = y - 3;
while KEYWORD ( LPAREN y IDENTIFIER >= COMPARISON t IDENTIFIER ) RPAREN y IDENTIFIER = ASSIGNMENT y IDENTIFIER - ARITHMETIC 3 INTEGER_LITERAL ; SEMICOLON

Running Example

int result = (3 + 4) * x;

The lexical analyser could produce a token sequence similar to:

TYPE(int) IDENTIFIER(result) ASSIGNMENT(=) LPAREN INTEGER(3) PLUS INTEGER(4) RPAREN MULTIPLY IDENTIFIER(x) SEMICOLON

The Symbol Table

The symbol table is an important data structure used by several compiler stages. It stores information about program identifiers such as variables, constants, functions and classes.

Identifier Type Scope Other information
result int local variable
x int local variable

The compiler can use this information later for declaration checking, type checking, scope analysis and code generation.

2. Syntax Analysis — Parsing

The syntax analyser, also called the parser, receives the token stream and checks whether the tokens follow the grammatical rules of the programming language.

INPUT

Token stream
→
PROCESS

Apply grammar rules
→
OUTPUT

Parse Tree / AST

The parser checks:

  • that tokens appear in a valid order;
  • that expressions follow language grammar;
  • that brackets and parentheses are structured correctly;
  • that statements contain the required components;
  • that the program can be represented using the language grammar.

Example of a syntax error

int result = (3 + 4 * x;

The opening parenthesis does not have a matching closing parenthesis.

Parse Tree vs Abstract Syntax Tree

Parse Tree Abstract Syntax Tree (AST)
Closely represents the grammar used by the parser. Represents the essential structure and meaning of the program.
May contain grammar nodes such as expression, term and factor. Usually uses operations and language constructs as the important nodes.
More detailed and verbose. More compact.
Closely reflects concrete syntax. Usually omits punctuation such as parentheses as separate nodes while preserving the structure they create.

Example AST

For the expression:

a * b + c

The root operation is +. Its left child is *, which has a and b as children.

3. Semantic Analysis

A statement may be grammatically correct but still make no sense. Semantic analysis verifies that the syntactically correct program also follows the meaning rules of the language.

INPUT

AST + Symbol Table
→
PROCESS

Type, declaration and scope checks
→
OUTPUT

Semantically checked representation

Semantic checks may include:

  • checking that identifiers have been declared;
  • checking variable and expression data types;
  • checking that operators are applied to compatible operands;
  • checking function arguments and return types;
  • checking scope rules.
Code Problem
total = number + 5; number may not have been declared.
age = "hello" + 5; Incompatible operand types for the intended numeric operation.
calculate(5, 8, 10); The function may expect a different number or type of arguments.

4. Intermediate Code Generation

The compiler now transforms the program into an Intermediate Representation (IR). IR is easier for the compiler to analyse and optimise than the original source code and is usually independent of a specific CPU.

INPUT

Checked AST
→
PROCESS

Convert program structure into IR
→
OUTPUT

Intermediate Representation

Running Example

Source code:

int result = (3 + 4) * x;

A simple three-address-style intermediate representation might look like:

t1 = 3 + 4 t2 = t1 * x result = t2

Temporary values such as t1 and t2 make each operation explicit and easier for later compiler stages to manipulate.

5. Code Optimization

Optimization improves the intermediate program without changing its intended behaviour.

The compiler may try to:

  • reduce execution time;
  • reduce memory usage;
  • remove unnecessary calculations;
  • remove unreachable or dead code;
  • simplify expressions;
  • improve loop execution.

Constant Folding

Before optimization:

t1 = 3 + 4 t2 = t1 * x result = t2

The expression 3 + 4 can be calculated during compilation.

After optimization:

t1 = 7 t2 = 7 * x result = t2

Dead Code Elimination

return total; total = total + 10;

The second statement can never execute after the return, so the compiler may remove it.

6. Target Code Generation

In the final compiler stage, the optimized intermediate representation is converted into instructions suitable for the target processor or virtual machine.

INPUT

Optimized IR
→
PROCESS

Instruction selection and register use
→
OUTPUT

Target / Object Code

Target code depends on the architecture for which the program is being generated. Different CPUs have different instruction sets, registers and machine-code formats.

Simplified Example

The compiler might eventually generate assembly-like instructions such as:

MOV R1, x MUL R1, 7 MOV result, R1

This example is intentionally simplified; real instruction generation depends on the target processor and compiler.

Compiler Architecture

Compiler stages are also often grouped into larger parts called the front end, middle end and back end.

Front End

Understands the source language.

  • Lexical analysis
  • Syntax analysis
  • Semantic analysis
  • IR creation

Middle End

Works mainly with intermediate representations.

  • Program analysis
  • Machine-independent optimization

Back End

Produces code for the target machine.

  • Instruction selection
  • Register allocation
  • Target code generation

Errors Detected During Compilation

Lexical Error

The source contains a character sequence that cannot form a valid token.

int @value = 5;

Syntax Error

Valid tokens appear in an invalid grammatical structure.

if (x > 5 {

Semantic Error

The syntax is valid, but the statement violates language meaning or type rules.

number = text * 5;

Linkers, Loaders & Library Routines

Generating object code is not always the final step before a program runs. Large programs may consist of multiple object files and use pre-written library code.

Library Routines

Library routines are pre-written and tested pieces of reusable code. They prevent programmers from having to implement common functionality repeatedly.

Examples include:

  • mathematical operations;
  • input/output operations;
  • string processing;
  • file handling;
  • graphical functions.

Linker

A linker combines object files and required library code into a program that can be executed.

The linker also resolves references between different program modules.

Loader

A loader is used when a program is launched. It places the executable program and required components into memory and prepares the program for execution.

Common Pitfalls

Token ≠ Lexeme

Lexeme: the actual characters in the program.
Token: the category assigned to those characters.

Example: total is a lexeme; IDENTIFIER is its token category.

Parser ≠ Parse Tree

The parser is the compiler component that performs syntax analysis. The parse tree is one representation that may be produced during parsing.

AST ≠ Parse Tree

A parse tree closely represents grammatical rules. An AST normally removes unnecessary syntactic detail and preserves the important program structure.

Syntax ≠ Semantics

Syntax asks: "Is this statement written correctly?"
Semantics asks: "Does this statement make sense?"

Compiler ≠ Linker

Compilation translates source program structures into target or object code. Linking combines separate compiled program components and resolves references between them.

Linker ≠ Loader

The linker works during the program build process. The loader works when the program is launched.

Self-Check Quiz

Q1: What does the lexical analyser pass to the syntax analyser?

A stream or sequence of tokens representing the meaningful elements recognised in the source code.

Q2: What is the difference between a token and a lexeme?

A lexeme is the actual character sequence in the program, while a token represents the category that lexeme belongs to. For example, count is a lexeme and IDENTIFIER is its token category.

Q3: What is the role of the syntax analyser?

It checks whether the sequence of tokens follows the grammar of the programming language and constructs a structural representation such as a parse tree or AST.

Q4: Why is an AST called "abstract"?

Because it removes unnecessary concrete syntax detail and preserves the important structural meaning of the program.

Q5: Which stage normally performs type checking?

Semantic analysis.

Q6: Does code optimization change what the program is supposed to calculate?

No. Optimization should preserve the program's observable behaviour while making its implementation more efficient.

Q7: What is the difference between the linker and loader?

The linker combines compiled program modules and libraries and resolves references during the build process. The loader places the executable program into memory and prepares it for execution when the program is launched.
