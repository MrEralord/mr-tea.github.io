Program Compilation Stages

Compilation transforms human-readable source code into lower-level representations that can eventually be executed by a computer. Along the way, a compiler recognises tokens, checks grammar and meaning, creates intermediate code, may optimise it, and generates target code.

The Compilation Pipeline

Compilation is not one giant translation step. It is a sequence of stages. Each stage receives an input, performs a specialised task and passes a new representation to the next stage.

1. Lexical Analysis

Reads source characters, groups them into lexemes and classifies those lexemes as tokens.

Two Broad Phases

At school level, the compilation process can be grouped into two broad parts: analysis, which understands and checks the source program, and synthesis, which constructs lower-level output from the analysed program.

Analysis

Breaks down source code, checks its structure and meaning, and builds an internal representation.

Lexical Syntax Semantic

Synthesis

Uses the analysed representation to create intermediate, improved and target-level code.

Intermediate Code Optimization Target Code
Extension: Front End, Middle End and Back End

Front End

Understands the source language: lexical, syntax, semantic analysis and usually IR creation.

Middle End

Analyses and improves machine-independent intermediate representations.

Back End

Selects target instructions, works with registers and produces target-specific code.

Quick Recap: Compiler, Interpreter and Assembler

Compiler

Translates a complete high-level program into object or target code before normal execution.

Interpreter

Translates and executes instructions during execution rather than first producing a standalone executable.

Assembler

Translates assembly-language instructions into machine/object code.

Real execution models can be hybrid

Java normally compiles source into JVM bytecode. Python implementations may also compile source into an intermediate bytecode before execution.

1. Lexical Analysis

The lexical analyser, or lexer/scanner, reads the source program as characters, groups characters into lexemes, classifies them as tokens, and passes a token stream to the parser.

Token vs Lexeme

A lexeme is the actual character sequence written in the source program. A token is the category assigned to that lexeme.

Tokeniser Lab

Edit the C-like statement and press Tokenise. This simplified classroom lexer recognises common keywords, identifiers, numbers, operators and punctuation.

1 Main Tasks of the Lexer

  • Read source code as a stream of characters.
  • Group characters into lexemes.
  • Classify lexemes as tokens.
  • Recognise keywords, identifiers, literals, operators and punctuation.
  • Usually ignore comments and non-significant whitespace.
  • Report invalid characters or malformed token patterns.

Whitespace is not always meaningless

In many languages spaces mainly separate tokens. Python is a useful exception: indentation has syntactic meaning because it marks blocks of code.

A statement can be grammatically valid but still be meaningless. Semantic analysis checks that the syntactically correct program obeys type, declaration, scope and operation rules.

4. Intermediate Code Generation

After analysis, the compiler can produce an Intermediate Representation (IR). IR is easier to analyse and optimise than the original source code and is usually less dependent on a specific processor.

Source expression a = b + c * d;
→
Three-address style t1 = c * d
t2 = b + t1
a = t2
→
Why? Simpler to analyse and optimize

2 Common Intermediate Representations

IR Idea
Three-address code Break complex expressions into simple instructions using temporary values.
Bytecode Intermediate instructions intended for a virtual machine.
Stack code Operations use a stack rather than many explicit addresses.
Postfix notation Operators follow operands, for example A B +.

5. Code Optimization

Optimization transforms intermediate code to improve efficiency while preserving the program's observable behaviour. The aim may be faster execution, smaller code or reduced memory usage.

Constant Folding

Calculate constant expressions during compilation.

Before: t1 = 3 + 4 t2 = t1 * x After: t1 = 7 t2 = 7 * x

Algebraic Simplification

Remove operations that do not change the result.

Before: y = x + 0 After: y = x

Dead Code Elimination

Remove instructions that cannot affect observable output.

return total; total = total + 10; Second line is unreachable.

Optimization must preserve meaning

The optimized program should still produce the same observable result as the unoptimized program.

After Compilation — Linker, Loader & Libraries

Generating object code is not always the final step before a program runs. Large programs may contain several object modules and use pre-written library routines.

Object Files and Library Routines

Object files are separately compiled program components. Library routines are pre-written and tested reusable code that can be linked into a program.

Linker vs Loader

Linker: combines object modules/libraries and resolves references.
Loader: places the executable into main memory and prepares it to run.

Common Pitfalls

Token ≠ Lexeme

total is a lexeme. IDENTIFIER is its token category.

Parser ≠ Parse Tree

The parser is the compiler component. The parse tree is a representation that may be produced during parsing.

AST ≠ Parse Tree

A parse tree closely reflects grammar rules; an AST removes unnecessary concrete syntax and preserves important structure.

Syntax ≠ Semantics

Syntax asks “Is it written correctly?” Semantics asks “Does it make sense?”

Compiler ≠ Linker ≠ Loader

Compilation translates program representations. Linking combines compiled components. Loading places the executable into memory when it is run.

Q1: State what is meant by program compilation. [1]

Reveal marking point
Translation of source/high-level code into lower-level, object or machine-executable form.

Q2: Describe two activities performed during lexical analysis. [2]

Reveal marking points
Any two valid points, for example: grouping characters into lexemes; classifying lexemes into tokens; recognising keywords/identifiers/literals/operators; ignoring non-significant whitespace/comments; reporting invalid character patterns.

Q3: Describe the purpose of syntax analysis. [2]

Reveal marking points
Checks whether the token sequence follows the grammar/rules of the language; builds a structural representation such as a parse tree or AST.

Q4: State two possible results of code optimization. [2]

Reveal marking points
For example: faster execution; reduced memory usage; smaller code; fewer unnecessary calculations/instructions.

Q5: Explain the difference between a linker and a loader. [4]

Reveal marking points
Linker: combines object files/library routines and resolves references during the build process. Loader: places the executable into main memory and prepares it for execution when the program is launched.

Self-Check Quiz

Q1: What does the lexical analyser pass to the parser?

A token stream.

Q2: Why is an AST called “abstract”?

It removes unnecessary concrete syntax detail and keeps the important program structure.

Q3: Which stage normally performs type checking?

Semantic analysis.

Q4: Why is intermediate code useful?

It gives the compiler a simpler, often machine-independent representation that can be analysed, optimized and later translated to target code.

Q5: Should optimization change the intended program result?

No. Optimization should preserve the program's observable behaviour.

Q6: What does a linker do?

It combines compiled object modules and required library code and resolves references between them.

Q7: What does a loader do?

It loads the executable into main memory and prepares it for execution.
