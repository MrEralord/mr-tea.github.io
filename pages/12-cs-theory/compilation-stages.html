Program Compilation Stages

Compilation is the rigorous process of translating high-level source code (e.g., C++ or Java) into low-level object/machine code that a computer's CPU can execute.

  • 12.5.1.3 Describe programme compilation stages: lexical, syntactic, semantic analysis, intermediate code generation, optimization, and target code generation.
  • 12.5.1.4 Understand the role of linkers, loaders, and library routines.

1. Retrieval: Translators Recap

Before diving into compilation stages, let's recall how translators operate.

Compiler Interpreter Assembler
Takes the entire source code in one go. Takes a single line of code at a time. Translates low-level assembly language.
Generates machine code / executable. Best for production. Does not produce an executable. Best for development. Generates specific machine code for a specific CPU architecture.
Class Discussion Trigger: "Which translator would you choose if you are testing your code line by line to find a bug? Which one if you are preparing the final release of your software?"

1 Lexical Analysis

  • Comments and non-significant whitespace are ignored and removed.
  • High-level code is grouped into a series of tokens.
  • Symbol Table Creation: Identifiers (names of variables, functions) are entered into the symbol table to store their attributes.

Tokens vs Lexemes

A lexeme is the actual character sequence in the source code. A token is the category that lexeme belongs to.

Code Segment: while (y >= 3) Lexeme Token Category
whileKEYWORD
yIDENTIFIER
>=COMPARISON_OPERATOR
3INTEGER_LITERAL

2 Syntactic Analysis (Parsing)

  • Checks the structural correctness of the token stream against grammar rules.
  • Produces a Parse Tree.
  • Produces an Abstract Syntax Tree (AST) by omitting unnecessary punctuation (like parentheses) while keeping the logical structure.

[Insert SVG: parse-tree-vs-ast.svg]

Description for creation: Side-by-side comparison for the expression a * b + c. Left: Parse Tree showing detailed interior grammar nodes (expr, term, factor). Right: AST showing just the operators + and * as nodes and operands as leaves.

3 Semantic Analysis

  • Verifies logical consistency. Ensures variables are declared before use.
  • Performs type checking (e.g., ensuring a string is not multiplied by a float).
  • Gathers data type information and updates the Symbol Table.

4 Intermediate Code Generation

  • Generates a machine-independent intermediate representation (IR) of the source code (e.g., Three-Address Code).
  • Acts as a bridge to facilitate cross-platform compilation.

5 Code Optimization

  • Improves the IR to reduce execution time and minimize memory utilization.
  • Eliminates dead code and calculates constants at compile time (Constant Folding) without altering the program's final output.

6 Target Code Generation

  • Translates the optimized IR into specific machine/object code tailored to the target CPU's architecture.

3. Modeling: The Pipeline in Action

Let's track a single expression as it moves through the entire compiler pipeline.

High-Level Source Code: An assignment statement containing mixed data types (float and integer).

float a = b + c * 60;

Lexical Analysis: The scanner removes whitespace and creates a stream of tokens. Identifiers go to the Symbol Table.

float id1 = id2 + id3 * 60;

Tokens: [KEYWORD], [ID, 1], [ASSIGN], [ID, 2], [PLUS], [ID, 3], [MULT], [INT_LITERAL], [SEMI]

Syntax Analysis: The parser builds an Abstract Syntax Tree (AST), enforcing operator precedence.

=
/ \
id1 +
/ \
id2 *
/ \
id3 60

Semantic Analysis: Checks types. Detects that '60' is an integer but 'c' is a float, inserting a conversion node.

=
/ \
id1 +
/ \
id2 *
/ \
id3 inttofloat(60)

Intermediate Code: Generates Three-Address Code (TAC), breaking the math into simple steps.

t1 = inttofloat(60)
t2 = id3 * t1
t3 = id2 + t2
id1 = t3

Code Optimization: Converts the integer to a float at compile time to save execution time.

t1 = id3 * 60.0
id1 = id2 + t1

Target Code Generation: Converts IR into CPU-specific assembly instructions.

LDF R2, id3
MULF R2, R2, #60.0
LDF R1, id2
ADDF R1, R1, R2
STF id1, R1

4. Post-Compilation: Linkers & Loaders

[Insert SVG: linker-loader-flow.svg]

Description for creation: Visual flow: file1.o + file2.o + Library Routines → LINKER → Executable (.exe) → LOADER → RAM (Memory).

  • Library Routines: Pre-written, pre-compiled segments of code (e.g., standard math operations). Reduces development and compile time.
  • Linker: Used during the build process. Links multiple compiled object files and libraries into a single executable, ensuring cross-references are correct.
  • Loader: Used at runtime. Loads the executable and required libraries into RAM and prepares them for execution.
