Backup & Disk Mirroring

Backup and disk mirroring both protect data, but they solve different problems. A backup gives you a previous recoverable copy. Disk mirroring gives you a live duplicate disk so the system can tolerate a drive failure.

Conceptual Anchor

Save Point vs Twin Disks

A backup is like a save point in a game: if something goes wrong later, you can return to an earlier state. Disk mirroring is like running two identical live copies at the same time: if one disk fails, the other still contains the current data.

Backup = previous point in time

A separate copy is created so data can be restored after deletion, corruption, malware or hardware failure.

Mirroring = current live state

Writes are duplicated to another disk in real time to provide redundancy if one physical drive fails.

The key sentence

Backup gives you another point in time. Mirroring gives you another live disk.

Data Backup

A backup is a separate copy of data kept so that the original data can be restored if it is lost, deleted, corrupted or damaged. Backups should be created regularly and stored separately from the original data.

3-2-1 Backup Rule

Keep 3 copies of important data, on 2 different types of storage, with 1 copy off-site. The purpose is to avoid one local failure destroying every copy.

Disk Mirroring — RAID 1

Disk mirroring writes the same data to two or more disks so that the disks contain identical current copies. A common implementation is RAID 1 — Redundant Array of Independent Disks.

Fault tolerance

Fault tolerance is the ability of a system to continue operating when a component fails. In RAID 1, data remains available from the surviving mirrored disk if one drive fails.

Backup vs Disk Mirroring

Feature Backup Disk Mirroring (RAID 1)
Timing Created at points in time / on a schedule Updated continuously as writes occur
Historical copies Yes — depending on backup policy No — stores the current mirrored state
Disk failure Can restore data from a separate backup System can continue using the surviving disk
Accidental deletion Can restore an earlier copy Deletion is mirrored to both disks
Ransomware / corruption A clean separate historical backup may allow recovery Corrupted/encrypted data is mirrored too
Main purpose Recovery Redundancy / availability / fault tolerance

RAID 1 is NOT a backup

Mirroring faithfully duplicates the current state. If a file is deleted, corrupted or encrypted by ransomware, that change is also written to the mirrored disk. RAID 1 protects against drive failure, not against every form of data loss.

Extension

Full, Incremental and Differential Backups

Organisations can create backups in different ways. A full backup copies all selected data. An incremental backup copies changes since the most recent backup. A differential backup copies changes since the most recent full backup.

Scope

Common Pitfalls

RAID ≠ backup

RAID 1 gives redundancy against a drive failure. It does not provide a historical version to restore after an accidental deletion or ransomware.

RAID = Redundant, not Random

RAID stands for Redundant Array of Independent Disks.

Mirroring ≠ remote backup

RAID 1 normally describes live redundant disks in the storage system. Keeping a separate backup off-site is a different protection strategy.

Backup must be separate enough to survive the same incident

A backup stored next to the original system may be lost in the same fire, theft or ransomware incident. Separation matters.

Reveal marking points

Q2: A company's server uses RAID 1. One hard disk fails. Explain one benefit of disk mirroring in this situation. [2]

Reveal marking points
An identical current copy of the data exists on the surviving mirrored disk. [1] The data/system can remain available while the failed drive is replaced/rebuilt. [1]

Q3: An employee accidentally deletes an important file from a RAID 1 server. Explain why RAID 1 does not allow the deleted file to be recovered. [2]

Reveal marking points
The deletion is also written/mirrored to the other disk. [1] RAID 1 stores the current state and does not provide an earlier historical copy of the file. [1]

Q4: Explain why an organisation may use both regular backups and RAID 1. [4]

Reveal marking points
RAID 1 provides redundancy / continued access if a physical disk fails. [1] The system can continue using the surviving disk. [1] Backups provide separate historical/recoverable copies. [1] Backups can restore data after deletion, corruption, ransomware or another event mirrored to both live disks. [1]
