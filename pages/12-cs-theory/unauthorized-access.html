Protect Data from Unauthorized Access

Preventing unauthorized access means controlling both who a user is and what that user is allowed to do. Effective protection combines authentication, authorization, access rights, sensible account controls and monitoring.

Learning Objective

  • 12.1.2.3 Protect data from unauthorized access
Core Idea Authentication Authorization Least Privilege Labs Monitoring Practice

Conceptual Anchor

The Hotel Analogy

At a hotel, reception first checks who you are. Then your key card only opens the rooms you are allowed to enter. Staff may have wider access, while guests have limited access. Logs can record when doors were used.

Two questions every secure system must answer

Authentication: “Who are you?”
Authorization: “What are you allowed to do?”

Authentication → Authorization → Access Decision

User Claims an identity
Authenticate Password, token, biometric or MFA
Check role & permissions Teacher, student, admin, guest...
Authorization result
ALLOW Access granted Requested action is permitted
DENY Access denied Requested action exceeds permissions

Successful authentication does not automatically mean full access. The system must still check authorization.

Authentication

Authentication is the process of confirming that a user is the person they claim to be.

Factor Meaning Examples
Something you know Knowledge factor Password, PIN
Something you have Possession factor Security token, smart card, authenticator device
Something you are Biometric factor Fingerprint, face, iris

Multi-Factor Authentication (MFA)

MFA combines factors from different categories. For example, a password plus a security token. If one factor is compromised, the attacker still needs the second factor.

Password Practice

Better practice Why it helps
Use long passwords or passphrases Longer passwords are harder to guess or brute-force.
Use a unique password for each service A breach of one account does not automatically compromise other accounts.
Avoid predictable personal information Names, birthdays and simple patterns are easier to guess.
Use a password manager Supports long, unique passwords without relying on memory.
Change a password if compromise is suspected Removes the usefulness of an exposed credential.

“Complex-looking” does not automatically mean strong

A short predictable password with symbols can still be weak. Length, uniqueness and avoiding known/predictable passwords are more important than simply forcing every user to add one symbol and one capital letter.

Authorization & Access Rights

Authorization determines what an authenticated user is permitted to access or change.

Permission Typical meaning
Read View data without changing it
Write / Edit Create or modify data
Delete Remove data
Execute Run a program or script
Deny / No access The resource or action is unavailable to that user

Role-Based Access Control (RBAC)

Instead of configuring every user separately, systems often assign users to roles. Each role has a predefined set of permissions.

Resource / Action Student Teacher Admin
View own marks Read Read Read
Edit class marks Deny Write Write
Create user accounts Deny Deny Create / Edit / Delete
Change system configuration Deny Deny Write

Authentication ≠ authorization

A teacher may successfully log in, but that does not mean the teacher should be allowed to create administrator accounts or change every system setting.

Principle of Least Privilege

The principle of least privilege means giving a user only the permissions needed to perform their role — no more.

Example

A school receptionist needs to view student names and contact details, but does not need to edit examination marks or create administrator accounts. The account should therefore receive access only to the required records and actions.

Why least privilege matters

If an account is misused or compromised, limiting its permissions also limits the amount of damage the account can cause.

Additional Controls

Automatic lock / timeout

Locks a session after inactivity so an unattended device is less likely to remain accessible to another person.

Disable unused accounts

Accounts belonging to users who no longer need access should be removed or disabled.

Audit logs

Record access and actions so suspicious behaviour can be detected, investigated and linked to an account.

Encryption reminder

Encryption protects confidentiality if data is exposed, but it does not replace authentication or authorization.

Preventive vs detective controls

Authentication, permissions and session controls help prevent unauthorized access. Audit logs mainly help detect and investigate what happened.

Common Pitfalls

Authentication ≠ authorization

Logging in proves identity. It does not automatically grant permission to every file, record or action.

MFA ≠ “two passwords”

Multi-factor authentication combines different factor categories, such as something you know and something you have.

Admin rights should not be the default

Full administrator access increases the damage possible from mistakes, misuse or a compromised account.

Audit logs do not directly stop an attacker

Logs provide evidence and visibility. They complement preventive controls but do not replace them.

Exam Practice

Q1: Explain the difference between authentication and authorization. [2]

Reveal marking points
Authentication confirms/verifies the identity of a user. [1] Authorization determines what resources/actions that authenticated user is permitted to access. [1]

Q2: Explain why multi-factor authentication can reduce unauthorized access. [2]

Reveal marking points
It requires evidence from more than one authentication factor/category. [1] An attacker who obtains one factor, such as the password, still needs the additional factor to gain access. [1]

Q3: A teacher can edit marks for their own classes but cannot create user accounts. Explain how authorization protects the system in this example. [2]

Reveal marking points
The teacher role is given only the permissions needed for teaching duties. [1] Administrative actions such as creating accounts are denied because they are outside the teacher's permissions/role. [1]

Q4: Explain why the principle of least privilege can reduce the impact of a compromised account. [2]

Reveal marking points
The account has only the permissions necessary for its role. [1] Therefore an attacker using that account can access/change fewer resources than if the account had wider/admin permissions. [1]
